# 2026-11-17 — Checks-Effects-Interactions (anti-reentrancy)

Pola paling dasar untuk mencegah reentrancy di Solidity: cek dulu, ubah state dulu, baru panggil kontrak luar.

```solidity
function withdraw(uint amount) external {
    require(balances[msg.sender] >= amount, "saldo kurang"); // 1. checks
    balances[msg.sender] -= amount;                          // 2. effects
    (bool ok, ) = msg.sender.call{value: amount}("");        // 3. interactions
    require(ok, "transfer gagal");
}
```

Kenapa urutannya penting: kalau `call` dilakukan sebelum saldo dikurangi, kontrak penyerang bisa memanggil `withdraw` lagi dari `receive()`-nya dan menarik dana berkali-kali sebelum saldonya berkurang — itu yang terjadi di serangan DAO 2016.

Aturan praktisnya: semua `require` dan semua perubahan state harus selesai sebelum ada `call`, `transfer`, atau panggilan ke kontrak lain. Untuk pertahanan berlapis, tambahkan juga `nonReentrant` dari OpenZeppelin.
