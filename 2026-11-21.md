# 2026-11-21 — Satu fungsi lupa modifier, itu celahnya

Di audit smart contract, bug access control paling sering bukan di fungsi
utama, tapi di fungsi saudaranya. `withdraw()` dikunci `onlyOwner`, tapi
`emergencyWithdraw()` atau `setFee()` yang dibuat belakangan lupa diberi
modifier yang sama — dan siapa pun bisa memanggilnya.

```solidity
// Fungsi ini terkunci...
function withdraw() external onlyOwner { ... }

// ...tapi saudaranya tidak. Ini celah nyata, bukan teori.
function emergencyWithdraw() external { ... } // SIAPA PUN bisa panggil!
```

Aturan praktisnya: setiap kali menambah fungsi baru, cek dulu semua fungsi
saudaranya — kalau 80% dari mereka memakai satu guard yang sama dan satu
fungsi tidak, itu hampir pasti bug. Pakai role-based access control
(misalnya OpenZeppelin `AccessControl`) supaya peran admin, operator, dan
pauser terpisah jelas, dan jangan pernah mengandalkan "fungsi ini kan
tersembunyi" — di blockchain semua fungsi public/external bisa dipanggil
siapa pun.
