# 2026-11-22 — Reentrancy: update saldo dulu, baru kirim ether

Reentrancy terjadi saat kontrak mengirim ether (atau memanggil kontrak lain)
SEBELUM memperbarui saldonya sendiri. Penyerang memakai fallback function
untuk memanggil `withdraw()` lagi sebelum saldo pertamanya dikurangi, dan
menguras dana berkali-kali dalam satu transaksi.

```solidity
// BERBAHAYA: kirim dulu, saldo dikurangi belakangan
function withdraw() external {
    uint amount = balances[msg.sender];
    (bool ok, ) = msg.sender.call{value: amount}("");
    require(ok);
    balances[msg.sender] = 0; // penyerang sudah re-enter sebelum baris ini
}

// AMAN: checks-effects-interactions, saldo di-nol-kan dulu
function withdraw() external {
    uint amount = balances[msg.sender];
    require(amount > 0, "saldo kosong");
    balances[msg.sender] = 0; // efek dulu
    (bool ok, ) = msg.sender.call{value: amount}(""); // interaksi terakhir
    require(ok);
}
```

Aturan praktisnya: urutan wajib checks (validasi) -> effects (ubah state) ->
interactions (panggil kontrak luar). Untuk fungsi yang memindahkan dana,
tambahkan juga `ReentrancyGuard` dari OpenZeppelin sebagai lapisan kedua, dan
jangan pernah percaya `msg.sender.call` selesai sebelum state diperbarui.
