# 2026-11-24 — Jangan pakai `tx.origin` untuk autentikasi

`tx.origin` adalah alamat dompet yang memulai seluruh transaksi, sedangkan
`msg.sender` adalah siapa yang langsung memanggil fungsi ini. Bedanya penting:
kalau kontrak A memanggil kontrak B, di kontrak B `msg.sender` adalah A tapi
`tx.origin` tetap dompet pengguna. Penyerang bisa memanfaatkan ini dengan
membujuk pemilik kontrak untuk memanggil kontrak jahat — lalu kontrak jahat
meneruskan panggilan ke kontrak korban, dan cek `tx.origin == owner` tetap
lolos karena origin-nya memang dompet owner.

```solidity
// BERBAHAYA: owner bisa ditipu lewat kontrak perantara
function withdraw() external {
    require(tx.origin == owner, "bukan owner"); // lolos via kontrak jahat
    payable(msg.sender).transfer(address(this).balance);
}

// AMAN: cek pemanggil langsung
function withdraw() external {
    require(msg.sender == owner, "bukan owner");
    payable(owner).transfer(address(this).balance);
}
```

Aturan praktisnya: selalu pakai `msg.sender` untuk autentikasi, jangan pernah
`tx.origin`. Satu-satunya pengecualian adalah menolak panggilan dari kontrak
lain (misalnya `require(tx.origin == msg.sender)` untuk memblokir bot), itupun
hati-hati karena memblokir juga wallet pintar seperti smart account. Di audit,
setiap kemunculan `tx.origin` langsung jadi temuan yang harus dijelaskan.
