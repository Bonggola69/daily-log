# 2026-11-25 — Modifier yang hilang di fungsi sibling adalah celah klasik

Saat audit, jangan hanya memeriksa fungsi yang punya modifier `onlyOwner` —
periksa juga semua fungsi "saudaranya". Celah paling umum: `setFee()` dijaga
modifier, tapi `updateFee()` atau `resetConfig()` yang mengubah state yang
sama ternyata lupa diberi modifier, sehingga siapa saja bisa memanggilnya.

```solidity
// BERBAHAYA: setFee dijaga, tapi resetFee tidak
function setFee(uint f) external onlyOwner { fee = f; }
function resetFee() external { fee = 0; } // siapa saja bisa memanggil!

// AMAN: semua fungsi yang mengubah state sensitif dijaga
function resetFee() external onlyOwner { fee = 0; }
```

Aturan praktisnya: untuk setiap state sensitif, daftar semua fungsi yang
menulis ke state itu, lalu pastikan semuanya punya guard yang sama. Kalau
80% fungsi sibling memakai guard dan satu tidak, fungsi itu hampir pasti
temuan. Di Foundry, uji dengan `vm.prank(attacker)` pada tiap fungsi tulis —
bukan hanya pada fungsi yang terlihat dijaga.
