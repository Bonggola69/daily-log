# 2026-11-26 — Reentrancy: ubah state dulu, baru kirim ether

Reentrancy terjadi saat kontrak mengirim ether (atau memanggil kontrak lain)
sebelum memperbarui catatannya sendiri. Kontrak penerima yang jahat bisa
memanggil balik fungsi yang sama di tengah jalan, dan karena saldo catatannya
belum berkurang, ia bisa menarik berkali-kali. Inilah pola serangan DAO 2016.

```solidity
// BERBAHAYA: kirim dulu, catat belakangan
function withdraw() external {
    uint amount = balances[msg.sender];
    (bool ok, ) = msg.sender.call{value: amount}("");
    require(ok);
    balances[msg.sender] = 0; // terlambat: penyerang sudah re-enter
}

// AMAN: checks-effects-interactions — catat dulu, kirim belakangan
function withdraw() external {
    uint amount = balances[msg.sender];
    require(amount > 0, "saldo kosong");
    balances[msg.sender] = 0; // efek dulu
    (bool ok, ) = msg.sender.call{value: amount}("");
    require(ok);
}
```

Aturan praktisnya: selalu ikuti urutan checks-effects-interactions — cek
kondisi, ubah state, baru berinteraksi dengan kontrak lain. Untuk pertahanan
lapis kedua, tambahkan `nonReentrant` dari OpenZeppelin pada fungsi yang
mengirim ether. Di Foundry, uji dengan kontrak penyerang yang memanggil
`withdraw()` lagi dari dalam `receive()`: kalau saldo bisa ditarik dua kali,
polanya masih salah.
